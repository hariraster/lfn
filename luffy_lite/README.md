# راهنمای IPv6 در Luffy Lite

این راهنما مکمل README اصلی است. پشتیبانی IPv6 از کتابخانه استاندارد Python استفاده می‌کند و وابستگی جدیدی ندارد.

## آدرس سرور در لینک اتصال

`VLESS_HOST` و بخش «آدرس سرور» در کارت، IPv6 ساده یا داخل براکت، IPv4، نام میزبان و URL کامل با طرح HTTP/HTTPS/WS/WSS را می‌پذیرند. نمونه‌های ورودی:

- `2001:db8::1`
- `[2001:db8::1]`
- `https://[2001:db8::1]/`
- `::1` یا `[::1]`
- `example.com` یا `https://example.com/`

`2001:db8::1` فقط یک آدرس مخصوص مستندسازی است و سرور قابل اتصال نیست؛ آن را با IPv6 واقعی و قابل دسترس سرویس خود جایگزین کنید. مقدار `VLESS_HOST` می‌تواند همان IPv6 واقعی، بدون براکت یا با براکت باشد.

IPv6 به شکل فشرده و استاندارد تبدیل می‌شود. در authority لینک و مقدار پارامتر `host` براکت‌ها حفظ می‌شوند؛ براکت‌های پارامتر query به‌صورت percent-encoded ذخیره می‌شوند. تمام آدرس‌های loopback، از جمله `::1`، لینک محلی WS بدون TLS با پورت ۸۰۰۰ می‌سازند؛ آدرس‌های دیگر لینک عمومی TLS با پورت ۴۴۳ می‌سازند. پورت و مسیر URL ورودی جایگزین پورت و مسیر ثابت لینک نمی‌شوند. IPv6 دارای zone identifier، آدرس ناقص و URL دارای اطلاعات ورود پذیرفته نمی‌شوند.

در کارت، آدرس را وارد و «اعمال آدرس» را انتخاب کنید؛ سپس لینک جدید را کپی کنید. ورودی نامعتبر پیام خطا نشان می‌دهد و لینک معتبر قبلی را تغییر نمی‌دهد؛ به localhost تبدیل نمی‌شود. نتیجه تشخیص آدرس مرورگر، انتخاب اعمال‌شده کاربر را بازنویسی نمی‌کند. «بازنشانی» به `VLESS_HOST` بازمی‌گردد و اگر آن تنظیم نشده باشد، آدرس صفحه را استفاده می‌کند. تنظیم نامعتبر `VLESS_HOST` نیز خطا نشان می‌دهد.

## پیش‌نیاز اتصال عمومی

نوشتن IPv6 در ورودی، سرویس غیرقابل دسترس را قابل دسترس نمی‌کند. میزبان باید واقعاً IPv6 عمومی، مسیر شبکه و دسترسی ورودی مناسب داشته باشد و WebSocket سفارشی سرویس را در دسترس قرار دهد. برای لینک عمومی، TLS و گواهی معتبرِ مورد قبول کلاینت برای همان IPv6 یا نام میزبان لازم است؛ یک گواهی مخصوص دامنه لزوماً IPv6 خام را پوشش نمی‌دهد. دامنه دارای رکورد AAAA و گواهی مطابق با دامنه نیز قابل استفاده است. دستگاه کلاینت هم باید به شبکه IPv6 دسترسی داشته باشد.

این قابلیت تضمینی درباره پشتیبانی IPv6 یا WebSocket سفارشی در Reflex Cloud یا هیچ میزبان دیگری نیست؛ امکانات واقعی میزبان باید جداگانه بررسی شوند. لینک loopback فقط به همان دستگاه کلاینت اشاره می‌کند.

## مقصدهای TCP خروجی

آدرس نوع ۳ در هدر VLESS تنها با ۱۶ بایت کامل پذیرفته می‌شود و با `ipaddress.IPv6Address` به شکل فشرده تبدیل می‌شود. اتصال TCP برای IPv6 literal صریحاً از خانواده `AF_INET6` استفاده می‌کند. IPv4 و نام دامنه همچنان از اتصال معمول asyncio استفاده می‌کنند؛ حل DNS دامنه می‌تواند رکورد AAAA را انتخاب کند.

هدرهای ناقص، طول آدرس ناکافی، دامنه غیرقابل رمزگشایی، فرمان غیر-TCP و پورت صفر رد می‌شوند، نه اینکه باعث IndexError یا خطای decoder شوند. هدر باید در نخستین پیام باینری WebSocket کامل باشد؛ هدر ناقص بین پیام‌های جداگانه بازسازی نمی‌شود. رفتار relay و مدیریت قطع اتصال معمول WebSocket حفظ شده است. دسترسی IPv6 خروجی نیز نیازمند پشتیبانی واقعی شبکه سرور است.
